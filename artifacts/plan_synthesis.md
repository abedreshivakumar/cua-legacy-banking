## Fixed stack
Python 3.12 via uv · Pydantic v2 · Playwright (Chromium) · pytest · typer CLI · JSON structured logging with a redaction processor · FastAPI/Starlette + Jinja for the mock target app · Anthropic SDK, model `claude-opus-5-5`, adaptive thinking, effort set explicitly.

Current Claude API facts that constrain the loop:
- Computer use on `claude-opus-5-5` = `{"type":"computer_toolset_20260801"}` (GA, no beta header, no name/display size). Calls arrive as `tool_use` blocks whose `name` is the member action (`screenshot`, `left_click`, `type`, `zoom`, …) with `toolset_name:"computer"`; possibly several per turn; every `tool_result` must echo `toolset_name:"computer"`; only screenshot/zoom need an image. Coordinates are in the pixel space of the screenshots we send.
- Forced `tool_choice` any/tool → 400. Use `auto` + `strict: true` custom tools + prompt steering.
- Thinking can't be disabled; default effort is `medium` — set it explicitly.
- History must be append-only (editing/pruning earlier turns invalidates thinking blocks). Do NOT prune old screenshots client-side; keep runs short or use server-side context editing (`clear_tool_uses_20250919`).
- Handle `stop_reason == "refusal"` → escalate.

## Key decisions
| Area | Decision |
|---|---|
| Target | Local deliberately hostile "legacy core banking" app: framesets/iframes, nested tables, no ids/test-ids, generated class names, labels in sibling `<td>`s without `for=`, duplicate/hidden Submit buttons, `<input type=image>` / `href="javascript:"` submits. Faults injected via `POST /__faults` admin endpoint (outside the agent allowlist), modes once/always/nth, seeded. Synthetic members only (100001–100020, SSNs in invalid 9xx range, masked display). |
| Flows | (1) Member inquiry (read-only): search member no. → detail → read share/savings balance + status; "NO RECORD FOUND - RC=04" for missing. (2) Internal transfer (risky): from/to share, amount, memo → review → confirm ("THIS TRANSACTION CANNOT BE REVERSED") → receipt TRN-xxxxxx. Server-side validation (amount ≤ balance, memo ≤ 30). |
| Perception | Discovery via computer toolset (screenshot + coords) plus a compact text element list as grounding aid. Viewport 1280×800, `device_scale_factor=1`, assert screenshot size == viewport. |
| Record-time targeting | On each act(): hit-test the coordinate (`elementFromPoint` recursing through frames with offsets) → snap to nearest interactive ancestor → generate multi-strategy target candidates (attr: form `name=`/submit `value=` · role+name · anchor: label text + relation same_row/right_of/below · table_cell: row label × column header · text · structural path relative to anchor · visual fallback) → validate each with the replay resolver (must uniquely resolve to the hit element) → act. Labels stored as `$labels.key`. Coordinates are evidence only, never in the artifact. |
| Custom strict tools | `type_secret(target, ref)`, `declare_input(name, type, value_ref)`, `record_output(name, type, region)`, `assert_checkpoint(description)`, `report_outcome(kind, name, rationale)`, `request_human(reason)`, `goal_complete(summary)`. Every tool requires a `rationale`. |
| Login | Scripted, outside the LLM loop; the same script is the replay re-login handler. Model never sees credentials. |
| Artifact | YAML for review, canonical JSON for `content_sha256`. Fields: schema_version, id, semver, status (draft/approved/suspect/deprecated), summary (agent-facing tool description incl. outcomes), app binding (vendor, product, version_range, surface), side_effects (read_only/reversible_write/irreversible_write = max step risk), labels, allowed_literals, inputs (typed, pattern, sensitivity public/internal/pii/secret), outputs (typed, sensitivity, extraction + transforms), outcomes (closed set of business outcomes), entry (route, login script ref, entry condition), steps (id stable across versions, intent, action, target descriptor with scope/frame path + expect guard + ranked strategies + min_confidence + quorum, value template, risk observe/navigate/input/query/commit_reversible/commit_irreversible, pre, post condition+timeout, idempotent), detectors (recoverable/hard_failure/escalate/business_outcome with condition, armed steps, priority, handler Dismiss/Relogin/Backoff → resume_step/retry_step/restart_entry, max_attempts, capture, origin recorded/explored/human/library), checkpoint (incl. identity check: the input member id visible on the result page), provenance (run id, model, transcript hash, compiler version, page signature per step), review (approver, sha256). Condition language: TextPresent, ElementResolvable, LocationMatches, FieldValueEquals, OutputsPresent, All/Any/Not. |
| Compiler | trace → drop no-op/failed actions → cut loops by (location, signature) revisits → collapse repeated typing → parameterize values equal to declared inputs; secrets → `secret_ref`; any other literal fails compile unless in reviewer `allowed_literals` → post-conditions (next step resolvable / route change) → risk (form submits/commit vocabulary default to commit_irreversible until reviewer downgrades) → outputs/checkpoint → attach vendor detector library → self-replay on original + second input must succeed before review. |
| Outcome detectors | Vendor detector library (session expired, system notice, 500, permission denied). Per-capability business outcomes via exploration pass: replay draft with probe inputs (nonexistent ID, invalid value) → snapshot divergent state → one bounded LLM call classifies + proposes TextPresent condition → accepted only if it matches the divergent state and none of the happy-path states → origin: explored → human approves. |
| Replay | Per step: check armed detectors → pre → resolve target with strategy fallback, confidence, quorum → act() (lease + policy + expect text guard) → race post-condition vs detectors vs timeout (never fixed sleeps). Recoverable → handler, bounded (per-detector max_attempts, run recovery budget 5, no-progress guard). commit_irreversible never auto-retried; ambiguous → failed(outcome_unknown, side_effects possible). Extract outputs → verify checkpoint → succeeded. |
| Result contract | Discriminated union on `status`: `succeeded` (outputs) · `business_outcome` (outcome, details) · `failed` (code: target_unresolved/postcondition_timeout/outcome_unknown/unexpected_state/checkpoint_mismatch/policy_denied/permission_denied/app_error/recovery_exhausted/input_invalid/control_lost; step_id, expected, observed, retryable, evidence refs) · `escalated` (intervention_id, reason, step) · `blocked_pending_approval` (reason, step). Common: run_id, capability, version, effective_sha256, tenant, trace (strategy used, confidence, recoveries, duration), side_effects_committed none/possible/yes, evidence_dir. |
| Safety | Single `act()` choke point for LLM loop, replay and approved human actions: lease check → resolve live target and classify the ACTUAL element → policy.check (ALLOW/DENY/ESCALATE + risk = max of action type, element text, route, form context, artifact annotation; artifacts can only raise risk) → act under lock → post-action URL/popup check. Network commit guard in `context.route`: off-origin blocked; state-changing requests blocked unless an active commit grant (one approved act + ~3s, route-scoped). `navigate` blocks javascript:/data:/file:/blob: (legacy JS hrefs stay clickable). Popups closed, downloads refused, service workers blocked. read_only goals: commit = deny. Discovery: commit → human approve-once (exact action). Replay: commit needs approved artifact with matching sha256 + single-use HMAC token bound to (capability_id, version, params_hash, nonce, exp) minted by a separate `approve-run` command; preflight returns blocked_pending_approval before launching the browser; re-check at the step. `prohibited` routes/text never automated. Policy YAML: environment, origins/routes allow/deny, navigation, actions + press_keys, secrets with allowed_targets, risk rules, modes, evidence settings. |
| Redaction | Sensitivity on every input/output. Compile literal deny-by-default + final artifact scan fails compile on PII-like hits. structlog processor (fail-closed): known values registry (secrets, params, encodings) → sensitive keys → patterns (SSN, Luhn PAN, email, phone, DOB, 8–17 digit account numbers). Screenshots in memory for the model; persisted only on failure/intervention with Playwright `mask=` (per frame); DOM snapshots redacted. Playwright traces only in mock env. Canary test greps all outputs for seeded password/SSNs/DOBs. Screenshots to the model provider are a data flow → synthetic data here; production needs ZDR + DPA. |
| HITL | Headed Chromium from the start for HITL-capable runs (fresh context, not persistent). Control lease {run_id, state, holder, expected_controller, epoch, intervention_id}; epoch bumps on every holder change; act() rejects stale epochs (ControlLost). States: AUTOMATION_RUNNING → PAUSE_REQUESTED → PAUSED_AWAITING_HUMAN → HUMAN_IN_CONTROL → HANDBACK_REQUESTED → REVALIDATING → AUTOMATION_RUNNING, plus approve-once / deny / ABORTED (TTL 15 min unanswered). Terminal is the authoritative channel (take control / approve once / deny / abort / Enter to hand back, `--operator` id). In-page banner shows who's in control; in-page hand-back button is convenience only. Recorder: context-level init script in every frame + `expose_binding`, captures click/change/submit/Enter, never sends password values, Python redacts to `{{param}}` / `[REDACTED:*]`; human events are untrusted and only become a draft revision (origin: human) for review. Revalidation on resume: origin/route OK, single page, not on login (else scripted re-login), replay resumes at first unsatisfied step; discovery gets a fresh observation + redacted summary of human actions. Hash-chained `audit.jsonl`. InterventionRequest schema: id, run_id, mode, kind (stuck/unrecoverable/approval_required/outcome_unknown/policy_violation/session_expired/agent_requested/unclassified_commit_attempt), goal, goal_intent, capability, step, proposed_action (param names only), reason_code, reason, detector, observation refs (masked screenshot, dom), recent_actions, allowed_responses, timestamps, status, resolution. |
| Stuck detection | max_steps 40 / time budget; state hash unchanged ×4; same action fails ×3 or 5 total; ≥3 policy denials; A↔B oscillation; model `request_human`; commit approval needed; unclassified commit blocked; re-login failed; replay: checkpoint fails after bounded retries, unknown dialog/state, commit timeout. |
| Process | Single Python process, asyncio. No services/queues. Optional mocked local operator page reads the same state. |
| Multi-tenant (design only) | Base artifact (vendor product + version range) → product-version patch → tenant overlay (typed ops keyed by stable step/detector ids: labels, prepend_strategy, add_detector, set timeout). Graceful degradation through `attr` strategy on shared form field names. Drift: soft (fallback strategy won, confidence drop, page-signature change) → flag; hard (target_unresolved/checkpoint_mismatch K of N) → status suspect + LLM-seeded rediscovery producing a diff for human review. Surface table: web frames ↔ desktop UIA/AX window/pane path ↔ pixel OCR+template. |

## Top risks
Coordinate→element resolution through frames · toolset protocol/scaling · compiler keeping exploratory actions · timing flakiness & false-positive detectors · handoff races & cross-frame capture. Spike the riskiest (M3 hit-test + 3-step real discovery; M5 handoff path) early.
